# Changelog

## 0.1.0 - unreleased

- Add logical partial-type metrics with declaration/member provenance and an explicit opt-in aggregate guard.
- Expose compilation diagnostics, unresolved names and incomplete context files without claiming project completeness.
- Add scope-labelled directed coupling, type/namespace cycle witnesses, a documented cognitive-complexity heuristic and instance-state cohesion groups.
- Import mutation-testing-elements v1/v2 scoring subsets with exact report digest and no final score for empty/pending runs.
- Guard production sources using a pinned published NuGet tool in local, CI and release paths.

- Library `Codemetr.CSharp`: Roslyn metrics per type and member (cyclomatic complexity, nesting depth,
  parameters, maintainability index, class coupling with type names, depth of inheritance, size).
- Configurable rules with file and type overrides, exclusions, inclusive limits.
- Ratchet baseline scoped to the analysed files and types; overloads keep separate entries.
- Tool `codemetr-csharp`: `analyze`, `check`, `baseline`; JSON and text reports; exit codes 0/1/2;
  `--files-from` for changed-file runs with the whole root as compilation context.
- Top-level statements and C# 14 extension blocks are measured.
- Warning when a type is declared twice in the compilation context.
- An existing baseline is only tightened by `baseline`; new or worse violations are refused.
- Renamed files keep their recorded debt when the value is not worse.
- Only the `<auto-generated>` header excludes a file; inactive `#if` code is reported.
- Quoted paths in file lists are an input error; report carries `schema`.
- Only a proven fix removes a baseline entry: code that moved into files that are never measured
  (generated parts, `bin`/`obj`, excluded paths) fails, entries hidden by inactive `#if` code or
  deleted in a file-list run stay until verified.
- `baseline` writes safe updates even when other entries are refused; `summary.skipped` counts
  generated and excluded files.
- Hidden members are matched by name; a root with linked folders leaves deleted entries unverified.
